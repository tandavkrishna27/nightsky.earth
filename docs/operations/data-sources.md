**Status:** Task 0A research draft, updated 14 October 2026. This is a source/terms screening, not legal advice or a production approval. Re-check exact product version, terms, attribution and coverage before ingest or launch. “Free” here means a zero-fee access path that appears to permit product use subject to listed conditions; it does not mean zero operating cost or an uptime guarantee.

## Current enabled data — 14 October 2026

The active meteor calendar uses the specifically rights-reviewed NASA MEO report NTRS 20250009524, all thirteen Table 3 forecast maxima for 2026 only. ## Implemented deterministic astronomy engine (Tasks 5–6)

**13 October validation update:** Task 5 meets its local acceptance criteria. The aggregate suite includes twelve USNO phase/season references and twenty-six JPL/NASA horizon, twilight, illumination, polar/boundary and solar partial-contact checks. Reviewed numerical reference dates are in 2024 and 2026; this is not arbitrary-date accuracy certification. Apparent topocentric AIRLESS altitudes differ from refracted upper-limb rise/set. Solar eclipse contact altitudes use standard refraction; lunar event altitudes are unrefracted. See [full source recipes and limitations](astronomy-validation-wave.md). The remaining lunar-contact, grazing-polar, near-horizon solar and fixed-J2000 Milky Way numerical boundaries remain explicit.

`astronomy-engine` 2.1.19 is pinned for local calculations and is MIT licensed. Its documented API covers Sun/Moon/planet positions, topocentric horizon coordinates, rise/set, and civil/nautical/astronomical twilight; its project states an angular accuracy target of ±1 arcminute and validation against NOVAS/JPL Horizons. V1 output records the package vintage and attribution. V1 tool windows are bounded to 5 days for darkness/twilight and 14 days for target altitude. Calculations expose geometric altitude and -18° astronomical twilight, not terrain/horizon, atmospheric extinction, seeing, or sky brightness. The Moon maximum altitude is sampled and labeled an estimate. The Milky Way core uses a fixed J2000 direction near Sagittarius and is a seasonal visibility approximation, not a deep-sky catalog. Sources: [Astronomy Engine](https://github.com/cosinekitty/astronomy), [USNO rise, set and twilight definitions](https://aa.usno.navy.mil/faq/RST_defs).

Task 6 uses the same pinned engine for Moon phase dates, seasons, and local solar/lunar eclipse circumstances. Solar eclipse contact altitudes use standard refraction; lunar event altitudes are geometric. Terrain and horizon obstructions are not modeled. A Reykjavik 2026 solar eclipse contact check is a narrow reference only. The eight-entry recurring meteor catalog stores normalized date windows and NASA source links, with a reviewed catalog vintage; it does not copy explanatory prose or claim radiant visibility or local meteor rates. Reuse rights remain unresolved pending Gate 0A, so the catalog must not be published until that review clears the source terms. Event classes outside the maintained calculations/catalog return explicit unsupported coverage. [NASA meteor-shower index](https://science.nasa.gov/solar-system/meteors-meteorites/meteor-showers/), [NASA 2026 events](https://www.nasa.gov/blogs/watch-the-skies/2026/01/16/most-notable-2026-astronomical-events-a-year-of-watching-the-skies/).

## Implemented weather baseline (Task 7A; live source gate open)

**13 October operational update:** MET published global documentation describes ECMWF coverage through ten days; actual returned field/horizon availability still needs representative live samples. Precipitation amounts/probabilities now retain their own overlapping aggregation intervals rather than overwriting short periods. MET and NOAA direct/planning/comparison requests share enforced upstream concurrency/call limits, duplicate-request coalescing, decoded-byte caps, response-body deadlines and provider cooldown. There is no scheduled refresh or automatic retry. See [provider controls](provider-controls-wave.md) and [MCP data flow](mcp-data-flow-and-logging.md). These local controls do not prove live sampling or deployment capacity. NOAA/NWS operational OVATION reuse screening passed with attribution, disclaimer, modification indication and no endorsement; the adapter provenance includes those conditions. Meteor-catalog reuse remains unresolved.

`get_night_conditions` now has a fixture-tested MET Norway Locationforecast 2.0 adapter and an MCP handler. It validates the documented JSON shape, keeps provider issue/valid times and units, omits missing fields, rounds requested coordinates down to four decimals, honors `Expires` and conditional `Last-Modified`, surfaces HTTP 203, and can return cached forecast as stale after a throttle/failure. Its planning context includes one requested local night (window capped at 24 hours), calculated astronomical darkness and Moon illumination, plus forecast valid times during darkness. MET remains the only forecast source in this increment; no second independent model is implied.

The adapter supports injected shared cache and rate-limiter implementations, but this worktree uses its process-local fallback unless the hosting layer provides shared instances. It has no scheduled refresh worker yet; only on-demand cache refresh is implemented, so refresh jitter is not applicable. The live sample gate remains incomplete: no owner-controlled application/contact User-Agent is configured, and tropical/midlatitude/high-latitude representative live payloads have not been captured. Do not claim provider readiness or public service coverage until Gate 0D records those samples and Gate 0F chooses how shared cache/rate limits operate across instances. MET describes global forecast horizons and fields as region/time-step dependent; its regional model guidance differs (MEPS/ECMWF in Nordic, AROME-Arctic/ECMWF in Arctic, ECMWF globally). [Locationforecast documentation](https://api.met.no/weatherapi/locationforecast/2.0/documentation), [data model](https://docs.api.met.no/doc/locationforecast/datamodel.html), [terms](https://api.met.no/doc/TermsOfService).

## Excluded source patterns

- Social-media/Instagram images and videos: V1 has no user media ingestion; public visibility does not grant scraping, storage, embedding or reuse rights.
- Noncommercial-only “free” datasets/services and unofficial mirrors: no product use without explicit permission.
- Public Nominatim or Overpass as the global production database: service policies/capacity do not support that assumption.
- Reproducing AMS/IMO calendars or DarkSky directory records without a reuse grant/license.
- Treating VIIRS ground radiance, weather averages, or mapped park tags as measured astronomical sky quality or proof of safe/legal night access.
