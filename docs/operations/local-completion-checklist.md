## Bounded implementation packets and dependency order

1. **Contract/privacy packet (2/3/4/12A/14):** validate locale via shared locale schema; implement requested display units without changing source-native records; preserve per-source identity/vintage/issue/valid times; remove silent attribution dropping; test worst-case eight-source/five-option output budget. Implement an explicitly allowlisted sensitive-metadata adapter and bounded short-lived subject counters if retaining that requirement, with no raw metadata/identifier logging or echo. Do not use IP as user identity.
2. **Events/targets packet (0A/6):** identify a reusable source for meteor dates/radiant/drift, document exact rights, epoch and uncertainty; implement pure coordinate/drift calculations only after source clearance; exercise horizon, date-boundary and Moon separation. Preserve unsupported classes. Add independent lunar/near-horizon references. A pure model with fixtures can be developed while catalog clearance remains open, but blocked data cannot enter a public artifact.
3. **Journey packet (10A/10B/11):** after target/event interfaces freeze, suggest up to three supported locally visible bright targets, produce bounded timed beginner/family guidance and activity-specific candidate windows. Preserve all option gaps/availability/windows, units and exact source-linked evidence. Map every product journey to an executable fixture or explicit measured coverage gap. Do not use unexplained universal scores.
4. **Candidate packet (0B/8):** real bounded OSM import, manifest/checksum/ODbL evidence, region/global projection, importer regression fixtures, actual artifact capacity and version rollback. Keep build and serving paths separate. This packet owns importer/index files and can proceed independently of event/contract code.
5. **Historical packet (0C/9):** keep verified 2025 sample working; quantify proposed multi-year/global baseline, bounded build limits, missing nights/bins and quantile prerequisites; retrieve only authorized bounded data; measure same-region baseline rather than extrapolating globally without evidence. This packet owns ERA5 files and can proceed independently of candidate/events.
6. **Operations/package packet (12–15/17):** build portable local rehearsal artifacts, exact review cases, package lint/secret checks and runbooks with explicitly unresolved host/identity fields. Final finished policies await publisher identity as required by Task 13. Prepare pilot definitions without inventing observations.
7. **Integration/CI closure:** freeze shared interfaces; combine real enabled artifacts with composed provider fixtures; run fresh Windows/Linux Node and Python checks, production smoke/audit, all-index bounded capacity and rollback. Commit/push authorized branch and record actual GitHub run URL/revision/conclusions. Hosted/release rows remain open.

Disjoint parallel lanes: candidate importer, historical builder, events pure calculations and operations prose/assets. Shared `planning.ts`, `common.ts`, MCP registry, planner/comparison and aggregate tests require one owner at a time. Contract packet precedes final journey integration; event model precedes meteor integration; all artifacts precede all-index capacity; frozen release precedes package digest and final CI.

## Completion rule

No deployment, purchase, public data publication, submission, marketplace availability or pilot result is established by this checklist.
