# Natural Earth offline ingestion contract

This adapter prepares explicitly mapped administrative geometry. It does not select a production source, acquire data, establish OSM extraction coverage, or prove candidate access. The existing gbOpen admission policy is unchanged.

Run `node --import tsx scripts/osm/natural-earth-ingest.ts INPUT.json NEW_OUTPUT` with previously acquired exact local bodies. There is no download or credential path. The CLI accepts only `natural-earth-v5.1.1`. `ingestSyntheticNaturalEarth` is a separate programmatic fixture seam accepting only `synthetic-natural-earth-only`, with synthetic boundary revisions and explicitly synthetic audit/completion identities. It cannot override production pins.

The input is a strict object with `schemaVersion:1`, `profile`, and exactly two `layers`, one per `level` (0 and 1). Each layer contains `input:{path,bytes,sha256,gitBlobSha1}`, `idField` and `mapping`. Paths are relative to the descriptor; hashes are lowercase hex. The Git identity is SHA-1 of `blob LENGTH\0` followed by the exact bytes. SHA-256 must be measured from the actual body. Fixed production lengths/Git identities are in `scripts/osm/natural-earth-policy.ts`; neither production body currently exists locally, so no production SHA-256 is claimed.

Each mapping explicitly binds a provider string ID to the existing RegionRef fields (`regionId`, `name`, `countryCode`, `adminLevel`, `boundaryRevision`, `sources`). Actual provider attribute names have not been established from retained body evidence: supply `idField` only after inspecting the actual pinned body. No field names or country identities are inferred. Missing, sentinel, duplicate, conflicting and unused IDs reject the whole preparation; no candidate processing or dropping occurs. Production normalization overrides supplied sources and edition with factual pinned Natural Earth provenance. Fixture provenance stays synthetic. ISO3 syntax follows the existing RegionRef schema; mapping correctness against actual countries still requires review.

Output is a fresh directory containing `boundaries.geojson`, `preparation.json`, `audit.json` and an atomically published `complete.json`. Existing output directories reject. Geometry retains all parts and holes. `preparation.json` feeds `prepareGeographicCoverage` with explicit normalized region ID mappings, no extraction polygons and no intended cells; it cannot create positive coverage. The normalized boundary pin in `complete.json` can be used directly as `boundaries` in the existing boundary membership descriptor alongside an independently pinned candidate stream and catalogue revision. Membership uses the existing unique strict interior rule: holes, borders, overlap and missing countries remain unknown and every candidate is retained. ADM1 beta omissions, disputed/overseas identity and generalized coastlines remain explicit audit limitations.

Geometry validation reuses existing conservative ring/intersection routines. Invalid rings, unsplit dateline edges, intersecting/touching multipart and nested multipart exteriors reject. This deliberately also rejects an island nested inside another part's hole. No repair, simplification, union, inferred state assignment or detailed geographic accuracy claim occurs.

Defaults: aggregate input 64 MiB, individual body 48 MiB, descriptor 1 MiB, 100,000 vertices, 10,000,000 work ticks, output 128 MiB, 60 seconds. Permitted ceilings are respectively 64 MiB, 48 MiB, 1 MiB, 1,000,000 vertices, 100,000,000 ticks, 128 MiB, 30 minutes. Limits can only tighten or stay below ceilings; they are rejection limits, not capacity estimates. UTF-8 decoding is fatal. Traversal, NTFS streams, Windows reserved names/trailing aliases/control characters, symlinks and canonical path aliases reject. Inputs are checked for open-file identity/stat mutation, SHA-256/Git pins and reread before publication. Output files use exclusive creation; the completion is written pending and renamed after final input/deadline checks. A failed directory may contain partial files or a pending marker and must never be consumed as complete. Concurrent hostile filesystem replacement cannot be fully prevented by portable Node filesystem APIs; use an operator-controlled workspace.

Retained immutable source evidence is `natural-earth-v5.1.1-license.txt` (4,636 bytes, SHA-256 `2631b5b39b6d1acc56de75235109b5af2dbb4b0ac5a127b6f06185977247fd4b`) and `natural-earth-v5.1.1-geojson-listing.json` (251,677 bytes, SHA-256 `85bd94a4e6cc3cd95cf9e54af5b6da1d8b9699b55ddefb229cc968d607c7af0a`). Both were copied byte-for-byte from existing local metadata evidence; no source acquisition occurred. The policy records the affirmative public-domain grant separately from the gbOpen policy. Actual body acquisition, measured hashes, explicit provider mappings, actual topology/resource fit and membership/filter acceptance remain open gates.
