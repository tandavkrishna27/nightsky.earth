3. **Only after successful format admission, propose one scale-discriminating request.** The same exact point and entire padded clock avoid spatial fillers and test useful long-series extraction. Freeze accepted date syntax, provider limit and explicit measured budgets first; do not silently expand the 24-hour allowance. Measure queue/submit/download/CPU separately, actual transferred and retained bytes, returned coordinates/time coverage and amplification. One point informs feasibility; it does not establish worldwide completion or queue guarantees. If long-series extraction is rejected, quantify an accepted split schedule before choosing CDS or moving to direct ARCO.
4. **Direct ARCO alternative only if needed:** separately admit authorized metadata access with explicit operation/byte caps; inspect chunk geometry and revision policy before selecting any value chunk. Then propose exactly enumerated metadata/chunk objects for one point and time window with a cumulative byte ceiling. A protected metadata response is no basis for speculative bulk chunk reads. Durable uncertain submission blocks replacement. Asset download carries no CDS token and follows no redirects.

The only allowed asset host is **`cds.climate.copernicus.eu`**. Retained evidence does not establish actual CDN/cache hostnames; a response naming another host stops before fetch. Keep the legacy sample as optional packaging diagnosis if later needed; it does not justify asking for permission now solely to pursue global coverage.
