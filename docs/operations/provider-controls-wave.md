# Provider operational controls

MET and NOAA now share process-local admission controls in production. Each runtime can inject one `UpstreamControls` instance into both providers using their `controls` option. A custom injected fetcher receives isolated default state for offline integration unless an explicit controls instance is supplied. Application wiring should reuse controls, cache, fetcher and limiter instances.

Conservative defaults (operational bounds, not a service availability promise): eight concurrent upstream operations globally, four per provider, 19 starts per provider per rolling second, 300 starts globally and 240 per provider per rolling 60 seconds, and 4 MiB of decoded response bytes per response. Bounds require positive safe integers. The existing MET 128-entry LRU and NOAA single-grid memory cache are preserved. Concurrency and call budgets count admitted transport work, not cache hits or duplicate waiters. Overload rejects immediately; there is no admission queue. The legacy injected MET limiter is supplementary and runs inside the request deadline after admission.

Same-request callers share downloaded bytes. MET keys include rounded coordinates, identifying User-Agent, conditional Last-Modified and dependency identity; NOAA shares its global grid across places but normalizes the result for each caller's place and window. There is no automatic retry or scheduled refresh. Refresh and recovery are demand driven. 429 and 5xx responses and transport/body errors block further calls for that provider using exponential backoff from one second, capped at five minutes. Retry-After integer seconds and HTTP dates increase the delay beyond that cap when requested by the server; malformed or past values use ordinary backoff. A concurrent successful request cannot erase a current cooldown. After cooldown expires the next admitted request attempts recovery. The five-minute cap applies only to locally computed exponential backoff, so long valid provider cooldowns are respected.

Native response streams are counted while reading and canceled once oversized; Content-Length can reject early but is never trusted as the only bound. This bounds decoded bytes (including responses without Content-Length), not compressed wire bytes or JSON parser overhead. Nonstandard injected test adapters without a body property retain their json/deadline contract; production must use standards-compliant Response streams.

The provider deadline covers transport, streamed body and injected MET limiter, even if they ignore abort. Abort cancels active native body readers and removes settled request signal listeners. A permanently abort-ignoring transport operation retains its occupied concurrency slot until it actually settles: releasing it immediately would permit an unbounded accumulation of background operations. Its coalescing entry is removed at abort. Such an adapter can exhaust available slots, causing later requests to reject admission; replacing a broken runtime is the recovery path. No persistent work or queue is created.

Expired cached MET forecasts and NOAA grids can be returned with explicit stale availability after timeout, upstream failure, throttling or admission refusal, provided the cached payload supports the requested interval. They keep original issue/valid times. No cached forecast is presented as freshly issued. Cached objects remain subject to existing schemas and horizons; malformed payloads retain the previous parse-error behavior.

These limits are per process. Multiple replicas multiply their allowed traffic; production replica count and externally shared provider budgets need deployment-level coordination before scaling. No database or distributed quota implementation is included. No new contact identity is supplied; MET still requires operator-provided identification.

Offline coverage: `tests/providers/upstreamControls.test.ts`, `tests/providers/providerOperational.test.ts`, existing provider deadline/LRU, MET normalization/conditional-cache and NOAA horizon tests. New files must be imported by `tests/all.test.ts` because the project runner uses that aggregate.

## Final integration verification — 13 October 2026

Both new suites are imported in tests/all.test.ts. Shared controls and per-source deadlines are forwarded through all direct and composed MCP paths; an actual MCP fixture proves one budget spans weather, planning, aurora and comparison requests. Windows and clean Linux each pass 207 aggregate tests, typecheck, build and production runtime smoke. Production dependency audit is zero; existing development findings remain recorded in implementation-status.md. Independent review found no remaining blocking scoped issues. No live upstream calls or deployment occurred in this lane.
