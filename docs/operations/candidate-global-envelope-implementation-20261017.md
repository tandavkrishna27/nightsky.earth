## Exact compatibility and controls

Both admission and Python supervisor accept only raw1/assembly1; raw2/assembly2/capacity2; raw2/assembly3/capacity3. There is no raw3. V1/v2 row/output/resource limits remain unchanged. V3 explicitly requires candidate rows C, membership output M, geometry comparisons and a validation object with physical read bytes/rows, lexical tokens, validation operations and control/admission read allowance Q. C is coupled to raw candidate allowance and publisher input rows, within the publisher's existing 10m maximum. M is the total membership output including common metadata and completion, within 64 physical 128 MiB parts plus bounded common metadata. No v3 value is a default or an execution approval.

Publisher and configured stream input byte controls cover at least M+F, where F is the reviewed footprint allocation. This covers enriched candidates plus their common regions and admitted footprint input; it cannot reuse a smaller raw-candidate allowance. Existing metadata-row, cumulative sort/output, page, memory and publisher deadline bounds remain. Geometry stays at most 200m comparisons and the original shared assembly deadline stays at most 30 minutes; neither is reset for a new part or final pass.

R is explicitly reviewed as `4*(B+M+F)+8MiB+3G+Q`: B is raw aggregate allowance, F footprint allocation, G maximum aggregate boundary input and Q bounded control/admission reads. Using allocation ceilings is conservative; actual pins must fit them. Physical source/admission validation reads include every input verification/readback, boundary staging/session pass, control reread and both assembly gate phases. Publisher internal scratch merge reads remain under the existing publisher mechanics/deadline/disk/row controls; this input-read counter is not all-process filesystem I/O telemetry. Publisher output/scratch writes are recorded separately from source reads.

## Resource identity and failure behavior

One authenticated session keeps the initial start time, absolute deadline, distinct 32 MiB metadata map, named counters and abort signal through all phases. Finite control discovery allows 3 MiB reads, 4m lexical/operation checks and 60 seconds; successful transfer preserves its actual charged start/counters instead of starting anew. An insufficient admitted Q/time/validation allowance rejects during transfer. Original source/authority/body hashes and current executable closure remain fixed and rechecked; the ordered TS/Python snapshot now pins 26 files including the new resource module.

Before-I/O reservations meter actual partition/JSONL reads, including EOF probes, with a closed body/control scope. Pinned control/copy/gate readers never request beyond precharged exact lengths; same-handle/link/stat/hash checks still reject mutation. Emitted boundary, membership, assembly and publisher writes are distinct. The assembly completion fixed point includes its own emitted bytes. Final raw/enriched/footprint/descriptor verification uses the same session after final admission. Failed physical output stays retained and unaccepted; both assembly and supervisor completion remain necessary.

A linear JSON scanner preserves duplicate-key/depth/UTF8 protections and lexical token definitions with periodic deadlines. Budget views stay bound to their original session/scope through async generators and I/O, so removing a field cannot fall back to an unmetered path. Outstanding read reservations also reserve operation headroom against concurrent writes. Metadata/geometry source authority has no caller override.
