# Offline spot acquisition safeguards

This implementation prepares the exact Monaco, Faroe Islands and Fiji dated source profiles from the proposal. It grants no retrieval authorization and has no live network CLI. `acquire_source` refuses to operate without an explicitly injected opener. Tests supply in-memory HTTP responses only.

`load_manifest` accepts a dictionary or JSON file path and requires version 1 plus the exact ordered three source dictionaries. URL, byte length, ETag, vintage, source page and license URL are pinned together. User URLs, substitutions, query strings, redirects and changed metadata fail admission. The canonical manifest digest is SHA-256 of sorted compact UTF-8 JSON.

Each injected acquisition performs at most one HEAD and one GET without retries. Repeated Content-Length, ETag or Content-Encoding fields are rejected, including identical repeats. Both responses must report HTTP 200, the exact URL, pinned Content-Length and ETag, and absent or identity Content-Encoding. The actual streamed count must equal the pin. SHA-256 is measured locally, not inferred from the ETag. Source header acceptance declares the PBF format explicitly so staged `.partial` files are parsed before promotion, and reads pyosmium's raw `osmosis_replication_timestamp` and requires exact expected vintage equality.

The lexical root and each ancestor are checked for symlinks and Windows reparse points before resolution. The caller provides an existing isolated root, an absolute monotonic deadline and an optional whole-wave budget callback accepting projected additional bytes. Acquisition applies its own 60-second ceiling, checks deadline and budget around every read and write, reserves the declared source body before GET, and checks zero additional bytes after writes. Supervision must separately enforce worker RSS and job memory, block descendants and enforce the total six-request wave budget. An injected opener is a trusted capability and must itself prohibit following redirects and obey its socket timeout; the wrapper rejects a changed final response URL but cannot undo requests made internally by an unsafe opener.

The exclusive staging file is retained on short/oversize replies, parse/header failure, budget failure or deadline expiry. No failure is accepted as empty coverage. Existing final or staging evidence prevents another attempt. Promotion occurs only after byte, digest and header checks, using exclusive destination creation. Failure evidence continues to count toward the shared 100-MiB budget; nothing is deleted to admit another source.

Tests include synthetic PBF header generation and in-memory HTTP metadata/body cases. These checks do not establish the real dated PBF headers, source hashes, source availability, measured regional build admission or full worldwide coverage. No archive HEAD/GET, account action, real source scan, download, deployment or publication is needed to run them.
