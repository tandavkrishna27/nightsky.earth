# Offline production history planner

`planProductionHistory(options)` in `scripts/era5/plan-production-history.ts` reads a locally pinned inventory and creates a new immutable proposal with exclusive file creation. It has no provider, account, request submission, download, authentication, model, or deployment entry point. Its status is always `unapproved-nonexecuting`. The ARCO/time-series route is documentation only and remains unadmitted; this planner proposes the existing legacy CDS identity only.

Supply absolute `inventoryPath`, its `expectedInventorySha256`, a new absolute `outputPath`, and an explicit finite `prefixJobs` (1–100). Pin the resulting returned SHA-256 before any separate future approval. Repeated generation into a different output filename produces identical bytes. Existing output files are never replaced. All input pins are revalidated before a synchronized temporary file is atomically linked into the final path; failed publication removes its temporary file. The strict CLI accepts `--inventory`, `--expected-inventory-sha256`, `--output`, `--prefix-jobs` and optional `--max-input-bytes`, `--max-verified-cell-hours`, `--max-duration-ms`; unknown, duplicate and incomplete flags fail. Paths must be absolute.

## Inventory admission

The exported strict `productionHistoryInventorySchema` requires schema version 1, gazetteer edition, timezone database version and 1–10,000 destinations. Each destination supplies a stable unique ID, display name, actual latitude/longitude, explicit supported IANA zone, coordinate/timezone/mapping provenance, uncertainty label and exact cell coordinates/ID. Provenance is an explicit operator assertion; this planner cannot verify a gazetteer edition's external contents. Unknown coordinates, timezone or mapping require resolving that gap before admission. There is no nearest-city or longitude timezone inference. Arbitrary-point zone suitability must be labeled unverified. Distinct names may share the same cell; source requirements deduplicate cells and aggregation requirements deduplicate cell/zone pairs.

Mapping uses the actual serving `suppliedCellKey` function: quarter-degree half ties round toward the positive quarter and the antimeridian normalizes to -180. Explicit source coordinates must agree with their cell ID and this function. The named coordinate and source coordinate both remain in the manifest. A named timezone does not establish timezone polygons or global civil-time coverage.

`completed` contains at most 4,000 relative local decoded partition paths with SHA-256, raw parent SHA-256, dataset `reanalysis-era5-single-levels`, variable `total_cloud_cover`, revision `0001`, and member zero. Use the retained ledger's partition records as input evidence, not the index/ledger JSON itself as a decoded file. Completed filenames, job names and declared coverage do not establish coverage. Paths reject traversal, symlinks and aliases through the existing trusted readers. Each decoded header must match its raw pin and final revision (decoder metadata `1` or `0001`, both the deterministic final ERA5 revision), and the existing decoder contract validates actual cells, sorted unique hourly timestamps, values and row count. Conflicting overlap values stop admission. Identical observations from separate final-revision parents deduplicate; all supplied parent/partition pins remain as lineage. Extra properties, including declared coverage assertions, are rejected.

## Clock, subtraction and proposal

The independent source clock is the compact half-open interval 1990-12-30T00:00:00Z to 2021-01-03T00:00:00Z: exactly 263,088 hourly positions per unique cell. It is generated from fixed boundaries independently of source rows. Only actual verified cell/hour rows subtract. A retrieved null remains scientifically missing but counts as already retrieved: absence of a valid fraction does not authorize a replacement request. Missing rows remain uncompleted. Completed rows outside this clock stop admission.

After subtraction, proposals visit canonical cell IDs, UTC months and missing hour shapes deterministically. Each request is one exact source cell and one year/month, grouping only days with the same missing hours. Its Cartesian days × hours contains no completed cell/hour. This conservative shape handles irregular retained coverage without silently fetching overlap and avoids guessing rectangular fillers. It is bounded by 744 hours, one cell and the existing 22,320-hour grouped parent ceiling. The proposal includes exact request parameters, dataset/revision/member, expected scalar hours and a hash of that identity. The prefix limit is explicit; the rest of the production schedule is not materialized. This is not an optimized grouping or measured job-count estimate. Provider acceptance of a degenerate one-cell area is unproved.

Requirements report unique cells, unique pairs, total scalar source hours, pair-hours, completed retrieved hours and remaining hours. The prefix reports proposed hours and whether it exhausts remaining requirements. Null validity is left to the downstream aggregation gates. No baseline quality or global coverage claim follows from a proposal. The supplied timezone version is retained as an inventory pin, not an assertion that this process installed that database edition.

## Local bounds and limitations

Input is capped at 1 GiB cumulatively (inventory 4 MiB; each decoded partition 4 MiB/800 rows), sparse verified observations at one million cell/hour rows, output at 8 MiB and elapsed work at 30 minutes. Lower explicit input, observation and duration budgets are accepted. Verification work includes duplicate rows in its budget. Memory contains only one decoded partition plus the bounded sparse retained-hour index, mappings and a finite request prefix; it does not allocate the full baseline clock per cell. These are cooperative bounds and do not establish a hard process RSS limit.

Manifest request limits retain raw 32 MiB, child 4 MiB/800 hours, and one active job as proposal constraints; no resource reservation or acquisition occurs. Full-grid storage, source revision assurance for a new format, runtime admission above 10,000 pairs, actual download bytes and provider acceptance remain separate review gates. No automatic retry, source substitution or approval follows from this output.

No retained private dataset body or network service is needed.
