# Event accuracy wave — 14 October 2026

## Design before implementation

Preserve the public event contract and the ordinary lunar eclipse journey. Replace unsupported ten-minute sign extrapolation with adaptive sign certification. For each segment, both endpoint signs and an altitude slope envelope bound possible interior excursions. A segment is certified when its endpoint distances from zero sum to more than the envelope times its duration. Otherwise evaluate its midpoint and recurse. Directly observed opposite signs establish partial visibility by continuity. Stop at one second or 4096 altitude evaluations, returning not-evaluated if same-sign intervals remain uncertified. Endpoints are always included.

Use a Moon-only 370 degrees/day envelope, slightly looser than Astronomy Engine 2.1.19's internal MaxAltitudeSlope global maximum: sqrt((360/0.9972695663 - 4.5)^2 + 8.2^2) < 357 degrees/day. Its RA and declination extremes are empirically determined upstream; the inequality is mathematical conditional on that envelope, not a universal proof of lunar ephemeris derivatives. No opaque SearchAltitude root search is used. The one-second floor is a computational uncertainty limit, not a crossing-time precision claim. Only geometric center altitude is established; terrain, limb/refraction, twilight and detectability remain excluded.

Tests will exercise narrow excursions missed by endpoints, tangent ambiguity, broad signs, directly witnessed crossings, and evaluation budget. Existing JPL Horizons AIRLESS fixtures independently check ordinary and rising lunar geometry. Those sparse reference values do not independently certify all extrema.

## Verified capabilities and remaining source gates

The exact installed sidereal-day ratio is 0.9972695717592592; the rounded design value changes no bound conclusion. Upstream supplies no formal date-specific proof of those empirical extrema. We therefore condition every same-sign interval claim explicitly on the model envelope across the entire interval, for every accepted input date; no real-sky or independently validated all-years guarantee is claimed. Extending formal derivative validation over the accepted date range remains a scientific validation gate.

The [library reference](https://github.com/cosinekitty/astronomy/blob/master/source/js/README.md) documents SearchRelativeLongitude for planet oppositions/conjunctions and SearchTransit for Mercury/Venus. These primitives do not establish all sky-plane conjunction minima, arbitrary occultations or transient-comet coverage. A future implementation needs explicit event definitions, independent timing references and local visibility limits. Current unsupported classes remain explicit: occultation, planetary-conjunction, opposition, comet and other.
