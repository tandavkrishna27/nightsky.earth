# Bounded candidate partition and merge design — 17 October 2026

Status: **reviewed design for coordinator implementation planning; not implemented or authorized execution**. Baseline `308fa0e3378a99afa53b9eac98a5a21fdc51f428`. Use current retained inputs only. No acquisition, inventory, deletion, serving change or global-completion claim follows from this document.

## Decision and feasibility boundary

Partition the **final ordered export from one existing SQLite normalization**, then classify all candidate parts in one membership session and feed all enriched parts into one existing catalogue build. Preserve the same raw source, selection policy, global deduplication, boundaries and unknown identities. “Merge” is a validated asynchronous stream, not a concatenated candidate file or a merge of independently published catalogues. The existing serving root/pages and query code remain unchanged.

This removes the individual 128 MiB candidate/exclusion/lineage file barriers while retaining **128 MiB per physical part**. It deliberately changes the logical-stream input contract: a candidate family may exceed 128 MiB, within an explicitly shared per-invocation aggregate envelope. It must not be described as an unchanged one-stream allowance. Direct emission and virtual concatenation avoid the old staged candidate copy and any second raw PBF or monolithic JSONL copy.

The existing proposal remains **385 MiB = 403,701,760 bytes** for its existing packets only. Version 2 instead requires a **mandatory explicit finite per-invocation aggregate normalized-output budget**, including all three evidence families, checkpoints and descriptors, admitted by an exact versioned reviewed capacity-plan pin. No default, inherited 385 MiB cap or automatic escalation applies to version 2. The aggregate must be a positive safe integer and fit the declared part cardinality, retained peak/reserve, supervisor disk/commit/wall, membership and publisher constraints. It is one shared allowance, never three independent family allowances. Keep one-million membership rows, 200-million checks, 30-minute membership wall and 1 GiB membership output globally unless a later separately explicit reviewed change addresses those independent ceilings. This is a necessary architecture change, **not proof any selected budget fits the world**. Current exact-planet minimum candidate + one-source lineage is 790 + 196 = **986 bytes per accepted object**. Even ignoring exclusions/descriptors/checkpoints, 1,000,000 accepted objects need at least **986,000,000 bytes**, exceeding 385 MiB; at most `floor(403701760 / 986) = 409433` hypothetical minimum objects fit that aggregate. Actual widths and exclusions lower it. Later Taginfo counts do not establish the absent dated body's accepted count.

Implement support for the explicit finite aggregate; do not choose or approve a larger actual invocation on the user's behalf. If actual output exceeds its declared aggregate, retain the failed attempt and report observed counts/bytes plus the exact deficit. Every changed invocation budget requires an explicit reviewed capacity version naming all changed numbers, coexistence/reserve/retention peak and supporting evidence before execution. The one-million-row and ten-billion-valid-node stops remain independent possible blockers. Partitioning supplies no exception to either. No sample-only pass may mark global feasibility complete.

## Versioned contracts

Keep legacy schema-version-1 production and library routes unchanged. Add strict version-2 raw manifest and assembly-plan branches; neither silently upgrades old input. Their full bytes are already admitted/pinned. The manifest adds `evidenceLayout: {kind:"partitioned-jsonl-v1", maxPartBytes:134217728, maxParts:64}`. Its existing `limits.outputBytes` is explicit, finite, positive and safe-integral; all other existing limits remain mandatory. The assembly plan requires the same layout, `maxNormalizedOutputBytes` exactly equal to the manifest value, a checksum-pinned `capacityPlan` (at most 64 KiB), and `maxCandidateInputBytes`, positive and no greater than that admitted raw aggregate. The strict capacity-plan version records the explicit family-total/output/scratch/staged-copy/failure/rollback allocations and exact stage/supervisor limits; its raw aggregate must match both manifest and plan. The versioned evaluator must reject unsafe arithmetic, aggregate-over-part-cardinality or incompatible stage allocations and negative reserve headroom. A capacity pin is evidence, not a source grant or permission to execute; actual operator authorization remains separate. This is an explicit aggregate candidate-input allowance, not a per-part reset. All three raw families together must still fit `limits.outputBytes`.

The new raw completion is a strict `schemaVersion:2`, `kind:"partitioned-normalized-osm-v1"` descriptor, at most **1 MiB**, with:

- Existing canonical full operational manifest SHA-256, selection policy, catalogue revision, geography mode, source-domain pins and admission snapshot SHA-256. The new layout participates in the version-2 manifest identity; never claim the old catalogue revision survives a different admitted manifest.
- A final source-completion/checkpoint witness: completed source count equals the exact manifest inventory, frozen SQLite checkpoint/database digest and counter digest. These are producer observations, not public estimates.
- Exact `streams` keys `candidates`, `lineage`, `exclusions`. Each family has `bytes`, `rows`, `sha256` of the **concatenated original bytes**, and ordered `parts`. Hashing concatenated part digests is invalid.
- Each part has contiguous zero-based `ordinal`, safe fixed-format relative `path`, `bytes`, `sha256`, `firstRow`, `rows`, and first/last ordered keys. `firstRow` is the zero-based ordinal within its family; ranges must cover `[0,totalRows)` exactly. Nonempty parts have positive rows/bytes and at most 134,217,728 bytes. There are at most **64 entries across all three raw families**, checked before allocation or path reads. Use fixed names `parts/candidates-00000.jsonl`, `parts/lineage-00000.jsonl`, `parts/exclusions-00000.jsonl`; reject caller-supplied alternate shapes, duplicates, links, traversal and unexpected completed-part files.
- Explicit empty families: zero parts/rows/bytes and SHA-256 of empty bytes. Missing family records are not empty evidence.
- Frozen per-source and global counters described below. Descriptor size, counter totals and safe-integer arithmetic are checked before referenced reads. Descriptor/checkpoint/counter metadata participates in the existing 32 MiB distinct metadata allocation, not a new allocation for each part. JSONL family bodies are not metadata: stream them with bounded row buffers and the declared cumulative raw-evidence byte/read/work/time ledger.

Raw rows retain their existing canonical UTF-8 JSONL bytes, full provenance, final newline and configured row ceiling, at most 4 MiB. Roll before the next **whole row** exceeds the part cap. An oversized single row rejects; never split or truncate its JSON. Lineage rows for one candidate (at most four) stay together. Exclusion duplicates may straddle parts and remain nondecreasing. All new file lengths, hashes, descriptors and checkpoint allocations enter the one existing `ResourceGuard`/output counter before writing; descriptor overhead is not free.

## Ownership, reconciliation and complete evidence

Keep the existing single database as the sole candidate reconciler. Equal OSM type/ID with the same body and native vintage merges source attribution; changed body or vintage rejects. Keep the four-source maximum. Do not independently select geographic/source partitions and choose winners afterward.

Candidate ownership is a contiguous ordinal interval of the existing `ORDER BY id` export. IDs must be strictly ascending **across part boundaries**, using the existing ASCII/BINARY lexical order, not locale sorting or numeric suffix ordering. Reject repeated IDs even if bodies are identical, omitted/overlapping ranges, unknown parts and reordering. Publisher deduplication must never hide a broken ownership proof.

Lineage is globally strict by `(placeId,source)` and preserves every distinct accepted pair. A bounded merge join over candidate and lineage iterators requires exactly 1–4 distinct source rows for every candidate, no orphan lineage IDs, and exact agreement with embedded candidate source IDs/hashes/vintages/policy and the admitted manifest source map. Compare each bounded ID group before advancing. Do not retain a planet-sized ID set.

Exclusions are independent complete evidence, ordered nondecreasingly by `(source,id,reason)`. The current table has **no uniqueness constraint**: preserve every identical tuple occurrence. An ID can be accepted in one source and excluded in another; neither discarding such exclusions nor applying them as a global removal list is allowed. Do not assign exclusions only to accepted candidate ranges, since most exclusions may have no accepted ID.

Persist per-source selected-tag occurrences `S`, accepted occurrences `R` and exclusion occurrences `E` in the same transaction as source selection. Require `S=R+E`. At frozen export, recompute `A=count(candidates)`, `L=count(lineage)`, `E=count(exclusions)` and per-source lineage counts from SQLite, then reconcile sums. Define duplicate accepted occurrences `D=R−L`, require `D>=0`, and `A<=L<=4A` (all zero for empty selection). Cross-source attribution is represented by `L−A`, not discarded as duplicate input. Checkpoints/counters must not double-count sources. The writer verifies emitted row counts against these frozen table counts, and the reader independently recomputes each stream's part/aggregate counts and hashes. These checks bind part completeness to **what the one producer selected**, not a claim that every real-world object was mapped.

## One membership session and one final consumer root

Refactor membership's input abstraction to accept either its old one-file pin or a strict admitted candidate-family iterator. For version 2, load and validate the **same full known/unresolved boundary inventory once**, build the BVH once and share one counter/deadline object through all parts. No geographic clipping or per-part region subset is allowed. The exact existing classifier, `1e-10` margin, borders/holes/dateline/polar behavior, candidate facts and unknown memberships remain unchanged.

Write enriched candidates directly as independently rolled **128 MiB parts**: input boundaries cannot be reused because region enrichment changes byte widths. Keep at most 64 enriched parts and a 1 MiB membership completion descriptor; all enriched parts, regions, empty generated footprint stream, descriptors and failure evidence share the existing **1 GiB membership output** allocation. Every input row and all geometry/index/revalidation work use the **one-million-row / 200-million-check / 1,800,000-ms** membership budget. The 64 KiB emitted-row ceiling remains. Emit common known regions once. Preserve unresolved competitors in classification, and retain only the original separately admitted footprint source for publication; membership parts imply no coverage.

The membership completion binds the exact producer descriptor hash, raw family hashes/counters, part inventory, plan/admission/code snapshot, boundary/footprint pins, cumulative resource totals and `inputCandidates=outputCandidates=A`. Reader errors and missing EOF invalidate all completion claims. Unexpected rows, revision changes, duplicate IDs, changed original facts or missing candidates reject before final publication.

Extend the source bridge with a bounded validator/adapter exposing enriched parts in ordinal order as **one `AsyncIterable<CatalogueCandidate>`**. It verifies all expected parts first, then rechecks during streaming, checks strict global IDs/counts and closes handles on abort. Feed that iterable to **one `buildStreamedCatalogue` invocation**, with regions and admitted footprints supplied once. Keep the publisher's single aggregate counters/deadline, global conflict detection and canonical final root. Do not publish each part or concatenate a larger candidate file. Require producer `A`, membership `A` and publisher observed **input** rows to match; publisher output dedup must not substitute for input reconciliation.

The existing schema-2 catalogue root with spatial, ID, name, membership, regions and footprints trees remains the runtime contract. `server/places/catalogueFormat.ts`, `catalogueFiles.ts`, serving cache and query code need no format change. Final assembly evidence pins raw completion, membership completion, exact plan/admission snapshot and this one root; success requires assembly **and** supervisor completion.

## Admission, retained accounting, failure and resume

Preflight admits the version-2 manifest/plan/layout, aggregate controls, source grants, boundary lineage and exact invocation; it cannot pin unknown future output hashes. The producer derives those hashes and binds them to the admitted snapshot, full manifest, policy and domain identities. Assembly verifies all three complete raw families and rechecks their descriptor, files and admission context before its final marker. Source-policy authority remains fixed; no partition can select reviews, change source vintage, omit a boundary or grant planet admission.

Extend both fixed executable lists to cover changed producer/driver code and any new partition helper, including `global_source.py`, `spot_paths.py`, `supervised_membership_assembly.py` and `global_source_supervisor.py`, in addition to the existing 17 files. Include any additional repository-local imports discovered by closure tests; no new loader process or dependency framework. Test ordered Python/TypeScript parity and actual byte mutation of each new execution dependency. Snapshot/lease/metadata checks remain bounded and candidate-controlled overrides remain impossible. Add an explicit version-2 maximum of 64 prelaunch accounting roots, checked before path expansion, inventory or Job creation, matching the receiver cardinality bound. The current assembly supervisor does not enforce this cardinality; do not describe it as an existing assembly check. Reject if the nonoverlapping retained set cannot fit this new strict guard. Outputs remain beneath the one accounted attempt root, not 64 new supervisor roots.

The first version **refuses partial raw-export, membership and publisher resume** before opening output. An incomplete attempt, partial part, index without completion or stale snapshot is retained failed evidence; no automatic retry, overwrite, cleanup or resetting of work/time/counters is permitted. Completed-output verification may be a read-only operation that checks the full descriptor/part/checkpoint inventory and current admission context; it does not resume execution or issue a new build completion. A new attempt requires its own explicit finite allowance and accounting for all retained failures. Legacy resume behavior stays isolated in the version-1 route.

If later partial resume is required, that is a separate design: reserve/charge remaining cumulative work, elapsed time and output before a durable checkpoint; charge crash-unknown work conservatively, count revalidation/index rebuild and reject changes to source/code/plan/part inventory. This plan does not introduce a checkpoint mechanism that resets budgets after a crash.

Proposed interfaces to keep producer/consumer work coordinated:

```ts
type PartPin = { ordinal:number; path:string; bytes:number; sha256:string;
  firstRow:number; rows:number; firstKey:string[]; lastKey:string[] };
type StreamFamily = { bytes:number; rows:number; sha256:string; parts:PartPin[] };
// Strict schemas—not unconstrained caller objects—construct these values.
verifyNormalizedPartitions(root:string, completionPin:Pin,
  expected:AdmittedProducerIdentity, budget:SharedPartitionBudget):Promise<VerifiedProducer>;
iteratePartitionedCandidates(producer:VerifiedProducer,
  budget:SharedMembershipBudget):AsyncIterable<CatalogueCandidate>;
// Definitions above must include bytes/rows/work/time/output counters and
// an absolute deadline; none are factories that reset counters on iteration.
```

`SharedPartitionBudget` is the explicit aggregate raw-evidence verification ledger; `SharedMembershipBudget` is the existing membership operation's one global ledger. `VerifiedProducer` holds validated immutable descriptors/pins and exact counters, never a full candidate list. `Pin` is a safe path/byte/SHA-256 pin; `AdmittedProducerIdentity` contains the expected manifest, revision, policy, domains, plan and admission/code identities described above. Keep producer writer code in Python and contract/classification adapters in TypeScript; no extra process, network or package dependency is required.

## Required evidence and rejection tests

Use TDD and focused fixtures first. A real **>128 MiB** synthetic JSONL family must span parts and reach the unchanged final consumer without materializing one oversized candidate file; label it a contract/limit test, not a global scale result. It must fit the declared aggregate and one-million-row budget. Small fixtures pin exact boundaries and failure semantics before this finite larger fixture runs once. Source maps/IDs may be synthetic, but no test-issued authority may enter production.

Required tests include: part rollover exactly at/one byte above cap; UTF-8/newline row boundaries; empty selection; one-row overflow; descriptor/part cardinality before reads; source/body/vintage conflicts across inputs; same accepted ID with multiple lineage sources; duplicate accepted occurrences and exclusion multiplicity; orphan/missing/reordered/repinned lineage and omitted exclusions; missing/repeated/extra/reordered parts and skipped ID ranges; digest/row-count/aggregate-hash tampering; linked/path aliases and changed bodies between precheck/stream/final check; changed code/plan/admission/domain/vintage on completed verification; abort or budget exhaustion after the first part; refused partial resume; publisher identical-row dedup unable to conceal repeated part IDs. Assert no accepted assembly/supervisor completion on every failed assembly. The existing publisher may already have written a physical catalogue root before a later producer/admission check fails; retain that root as failed evidence and never accept or install it without both successful final markers. This design does not add a separate root-publication staging mechanism.

Compare version-1 and version-2 selected candidate facts, full lineage/exclusions, membership unknowns and final consumer-visible query results on the same synthetic inputs and already retained normalization metadata. Preserve exact border/holes/dateline/polar/unresolved semantics. Check one global row/work/time/output counter across at least two parts; a second part must fail when it would exceed the remaining allowance. Verify common regions/footprints occur once and every committed body remains immutable. Run focused admission/supervisor integration, typechecks and exact-tip six-job CI once code is stable.

Global completion still requires the actual authorized planet identity/native evidence, complete producer observations, accepted source/boundary admission, fully completed bounded assembly/publication and catalogue/serving measurements. Until those exist, report the exact next blocker and observed deficit; do not promote the larger synthetic contract test, the retained 500-point parity sample or this design into worldwide completion.
