# Offline geographic preparation

`node --import tsx scripts/osm/prepare-geographic-coverage.ts INPUT.json NEW_OUTPUT` prepares local pinned inputs. It makes no provider requests and admits no real edition by itself. Every example in its tests is synthetic.

The strict version 1 manifest contains:

- `boundaries`: `input` pin, `idField`, and `mapping` object keyed by exact string provider IDs. Each value is a complete shared `RegionRef` (versioned region ID, name, ISO3 country code, level 0/1, revision, 1–4 source records). All features and mapping entries must match exactly once. Missing, duplicate or unused IDs reject. Original provider metadata and licences must be retained in the pinned input or separately admitted source archive; mapping/provenance is retained in audit.
- `extractions`: up to 100 records, each with `input` pin, `evidenceKind: "extraction-polygon"`, exact `edition` and 1–4 `sources`. Only explicitly asserted extraction evidence establishes source coverage. The operator must independently admit that association with the source snapshot; the tool cannot establish it from arbitrary geometry.
- `intendedCells`: explicitly enumerated ordered rectangular `{west,south,east,north}` cells. This inventory defines the audit scope. It is not an implicit world inventory.

Every pin is `{path,bytes,sha256}`. Paths are local relative paths without traversal, drive names or symlink components. Descriptor and inputs are captured within a cumulative byte budget; input files use fixed-size reads, identity checks and final byte rechecks. Output roots must be new. Mutation, invalid input, cancellation or exhausted work leaves no accepted completion marker. Partial output remains for inspection. `complete.json` is renamed last and pins all preceding artifacts; its own bytes also count against the output limit.

Provider properties are replaced only by the explicit mapping; coordinates are preserved. Polygon/MultiPolygon, two dimensional coordinates, closed simple nondegenerate rings and strict hole ownership are validated by the same geometry helper used by `boundary-metadata.ts`. No simplification, snapping, hole removal or dateline splitting is performed. Longitude edges over 180 degrees reject. Already split dateline islands remain separate. The preparer additionally rejects touching, overlapping or nested multipart components; valid island-within-hole arrangements are conservatively unsupported. Independent administrative features may overlap and remain available for the membership producer's existing ambiguity rules.

`boundaries.geojson` is accepted by the existing boundary producer. `footprints.jsonl` uses the existing strict `geometryBasis: "full-cell"` schema and is accepted by the source catalogue bridge. `audit.json` retains all manifest pins, source records, mappings, modifications, counts and every residual intended cell. Administrative geometry, point bounds and candidate counts never establish extraction coverage.

A footprint requires all four corners strictly inside one extraction polygon, outside all holes, with no polygon boundary vertex inside the closed cell and no boundary edge touching/crossing any cell edge. This rejects a hole wholly inside the cell and a concave indentation crossing it. Cells touching extraction boundaries remain residual. Coverage spanning multiple extraction parts is deliberately not unioned: seam cells remain `not-proven-in-single-extraction-part`. Islands are assessed separately, and dateline parts never fill the intervening longitude gap. Cells reaching absolute latitude 85 degrees remain `polar-exclusion`. Duplicate ownership deterministically follows manifest extraction order. Output retains the owner's source records; audit retains every input source. No independent admission of extraction union, polar coverage, selected-object completeness, overseas territory completeness or worldwide coverage follows from this preparation.

Default/hard limits: cumulative input 16/64 MiB, vertices 100,000/1,000,000, comparisons 10/100 million, intended cells 10,000/100,000, all output 16/128 MiB, elapsed time 60 seconds/30 minutes. API options are `maxInputBytes`, `maxVertices`, `maxComparisons`, `maxCells`, `maxOutputBytes`, `maxMilliseconds`, `signal`. CLI uses defaults. Deadline checks are cooperative during geometry, reading and writing; JSON parsing and filesystem calls are bounded by bytes but cannot be interrupted mid-call. Total RSS is not enforced here; a process supervisor remains necessary. Exact resource feasibility of real worldwide data remains unproven.

Targeted tests exercise the actual boundary producer, source bridge and empty covered discovery query, holes, concave crossings, split dateline islands, border/polar residuals, unsupported geometry, mapping ambiguity, checksums, budgets, cancellation, input mutation and immutable outputs. Initial tests were added after implementation, so no initial RED observation is claimed.

Provider collection and feature structural fields are strict: collections allow only `type` and `features`; features allow only `type`, `properties` and `geometry`. CRS declarations, bbox, feature-level id and foreign structural metadata reject rather than being silently stripped. Provider IDs must occur in the explicitly named properties field. Only ordinary provider properties are replaced by the mapping. Geometry allows only `type` and `coordinates` through the shared validator. Inputs must already be longitude/latitude GeoJSON with no CRS override; projected coordinates are unsupported. A root/feature EPSG:3857 regression was observed failing before this fix and passing afterward.
