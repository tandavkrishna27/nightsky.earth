# NightSky source, attribution and content-rights register

Reviewed 18 October 2026 against the website source and the separate MCP worktree's `docs/operations/data-sources.md`, deployment notes, and provider/data-flow documentation. This is an operational evidence register, not legal advice, a blanket permission grant, or proof that a provider is enabled in production. Optional providers depend on private deployment configuration, which was not inspected. Source/operations documentation was updated; plugin runtime code and configuration were not changed.

## Hosting, audience and data handling facts

- The owner has confirmed Hetzner as the intended host for the MCP server. The server is not yet deployed there, and the product/region, DNS, TLS, proxy, firewall, log settings, retention and backup settings have not been verified. Netlify currently hosts the website and its news function; its plan and account-level retention remain unverified.
- The owner has confirmed an 18+ audience. The website Privacy Policy and Terms already say 18+. The reviewed MCP policy draft still says 13+; that mismatch must be corrected in the plugin worktree before its release. The separate MCP policy remains a release task; this register does not change its audience setting.
- The MCP implementation reviewed does not retain user request/conversation history or user locations as persistent records. It uses bounded process-memory rate counters and provider caches, and it has a persistent provider-quota ledger. Optional offline historical-data preparation can create location/date-bearing research artifacts. Application and reverse-proxy logging/retention on Hetzner remain unverified. Reconcile the public Privacy Policy with the actual deployment before the MCP endpoint goes live.
- Provider integrations are conditional. Source code and documentation do not establish which private environment switches will be enabled on Hetzner. Do not present optional integrations as live until the deployed configuration is checked.

## Release decisions and evidence checklist

1. Website meteor-calendar rights remediation is complete: AMS-derived dates were removed and eight year-specific NASA MEO maxima retained with report-level attribution and precision notes. AstroPixels data reuse remains subject to its exact required acknowledgment. Owner confirmed the existing photos/video are generated or owner-created.
2. Before distributing the OSM candidate index, create and review the exact machine-readable database or alteration/build-file offer, source lineage, vintage, modification marker and attribution. Keep public index release gated until that artifact exists.
3. Before the MCP goes live, record the actual Hetzner product, region, hostnames, DNS/TLS, proxy/firewall, enabled source switches, exact artifact hashes, attribution surfaces, access-log fields, rotation/retention, backups, operator access and deletion procedure. Test the public MCP route and review logs using synthetic requests.
4. Reconcile the MCP draft audience from 13+ to the owner-confirmed 18+ in the plugin worktree before release. This repository change intentionally records the mismatch; it does not modify plugin files.
5. Recheck website Privacy wording against actual Hetzner and provider behavior immediately before the endpoint is enabled. No login/account data collection was found, but host/provider technical logs and optional historical artifacts have different data flows.
6. Have the owner approve the source and asset rights decisions and obtain qualified legal review of the public Privacy/Terms before launch. Keep approval dates unset until approvals and host evidence exist.
