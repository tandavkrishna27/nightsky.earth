## Finite plan and execution

The plan was written before the single retained run; the parent explicitly scheduled it while the historical lane waited. Limits are 600 seconds shared across raw production and catalogue publication, 1 GiB main-process RSS, 2 GiB whole-job committed memory, two processes and 96 GiB free disk reserve. New job writes have a 1 GiB ceiling; the tiny manifest/control/evidence files are additionally counted within the enclosing 4 GiB authorized allocation. Raw SQLite scratch is limited to 512 MiB, normalized output to 64 MiB, and publisher input/output/scratch individually to 64 MiB with a 120-second publisher deadline. These are stop ceilings, not worldwide capacity estimates.

The current interpreter and optional installed pyosmium are used; no dependency install is attempted. The child producer and bridge run sequentially through the existing suspended-launch Windows Job supervisor. Job committed-memory/process caps are hard controls. Main RSS, file lengths, reserve and deadline are sampled; they can overshoot between polls. All outputs are new ignored `.data/osm/retained-geography-20261015-v1-*` paths. Existing retained data is preserved.

A reproducible invocation requires an exact pinned local manifest (see the raw pipeline contract):

```text
python scripts/osm/measure-retained-source.py MANIFEST.json NEW_JOB_DIRECTORY --python EXISTING_PYOSMIUM_PYTHON --seconds 600
```

The harness writes a pinned configuration and empty metadata beside the job before execution, then runs the real producer and bridge under the common deadline. Manifest inputs must have coherent declared native vintages; the raw producer independently checks native headers and source size/hash before and after processing. An existing job/control directory is refused. There is no automatic retry or cleanup. Measurement controls and retained inventory must be included in the operator allocation; the generic supervisor cannot discover unrelated editions.

## Meaning of the measurements

Per-stage wall time comes from the existing supervisor. Per-stage CPU, peak tree commit and transfer-byte counters come from the Windows Job accounting information just before its handle closes, after all descendants have drained. CPU includes descendants; main RSS is sampled separately and must not be equated with whole-job memory. Job transfer bytes include cached and metadata I/O and are **not physical raw-source read volume**. The final retained SQLite node table describes only the last source because the producer clears nodes between sources; it is not a sum of both sources.

SQLite, rollback/WAL/shared-memory journals and other job-file lengths are sampled independently; each peak may occur at a different time, so their sum is not the measured simultaneous peak. Final logical lengths are recorded separately. Hashing and JSONL publication occur within the producer stage; their individual durations are not instrumented and are explicitly null. The catalogue publisher is the actual second stage. Source hashes are independently rechecked after the run. No compressed-size throughput extrapolation or global-fit claim is made.

The retained checkpoint records one completed source (Monaco), but no canonical candidate JSONL or `complete.json` was published. Faroe was underway. Sampled main-PID RSS was **4,386,816 bytes**, which may describe the Windows virtual-environment redirector rather than the producer worker; it must not be presented as producer/tree RSS. Logical Job transfer counters recorded 32,237,921 read bytes and 3,087,334 write bytes. Cache and host background load were uncontrolled, with no cold-read guarantee. The final SQLite file was 1,204,224 bytes and its rollback journal 1,183,232 bytes. These figures establish the bounded attempt's behavior, not a global throughput estimate or maximum SQLite size.

A read-only SQLite count query after drain refused hot-journal recovery (`attempt to write a readonly database`). No recovery or write was attempted; partial node/candidate counts remain unavailable. Native canonical adapter validation and actual bridge performance remain unmeasured for these retained PBFs.
