## Recommended source decision

Retain public Geofabrik OSM snapshot PBFs as the candidate source. The concrete candidate edition is the eight root-level `*-261013.osm.pbf` files already enumerated in source admission: Africa, Antarctica, Asia, Australia/Oceania, Central America, Europe, North America and South America. Stored directory lengths total **85,563,268,782 bytes (79.69 GiB)**. These lengths, availability and header vintages were not revalidated here. Do not substitute `latest`, merge country children, refetch Monaco/Faroe/Fiji or add a planet automatically. A dated edition that disappears requires a new proposal.

Prefer **gbOpen ADM0 and ADM1 at one immutable geoBoundaries repository commit**, with per-layer original metadata and geometry pins. Choose the commit and enumerate every country/territory/absent level in a metadata admission pass before requesting bodies. No specific current commit or complete boundary file inventory has yet been admitted. The documented **5.0.0 / b7dd6a5 / 19 December 2022** archive is a reproducible fallback, not a current-boundary claim. Resolve a full commit SHA before use. A modern commit is preferable if its complete metadata, coverage and rights pass review. This is a concrete source family and edition-selection rule, not a claim that a worldwide boundary edition is ready.

## Actual interfaces and remaining implementation

The raw producer, SQLite identity/lineage merge, streamed catalogue bridge, Windows process supervisor and strict membership producer now exist. They must not be described as missing wholesale. They do not perform acquisition, provider-geometry conversion, clipping-union construction or global boundary orchestration.

The streamed publisher has a separate executable ceiling: `build-streamed-catalogue.ts` defaults to **60 seconds, 128 MiB each of input/output/scratch and 100,000 input rows**. Its API hard ceilings are **30 minutes, 10 GiB each and 10 million input rows**; metadata stays capped at 10,000 rows. The four-path `build-source-catalogue.ts` CLI passes no limit overrides. Before the production tranche, implement and review a bounded caller/configuration path and a partition plan that preserves one coherent catalogue revision, global duplicate resolution and cross-partition membership ambiguity. Independent roots cannot simply be concatenated into a valid global edition. The aggregate 12 GiB output allocation below does **not** raise the single-publisher 10 GiB hard cap. Prove a complete edition fits one admitted publisher call, or implement a reviewed coherent composition route before scaling. Larger raw-source budgets do not change these publication limits.

Boundary provider GeoJSON cannot be passed directly to `boundary-metadata.ts`: each feature must have only type/properties/geometry, with properties exactly the shared `RegionRef` fields. Map provider IDs to stable `region:v1:...` IDs; retain source IDs and full metadata in a pinned sidecar, source records, country ISO3, level, revision and modification audit. Validate names (160-character schema maximum), revision (100 maximum), 1–4 source records and country identity. Do not copy arbitrary provider properties or invent missing levels.

Implement a deterministic local normalization/preflight adapter: Polygon/MultiPolygon, two-dimensional longitude/latitude, closed simple nondegenerate rings, retained holes/islands, proper antimeridian splits, no edge longitude jump over 180 degrees, and rejection reports for invalid topology. Splitting must preserve hole ownership; a bounding rectangle or dropped ring is unacceptable. Prefer unsimplified provider geometry, partitioned safely; simplified files require measured membership error acceptance and explicit modification provenance, not just lower byte counts.

The boundary producer loads geometry into memory and uses comparison budgets. Defaults are 16 MiB/100,000 vertices/10 million comparisons/100,000 candidate rows/128 MiB output; hard configurable ceilings are **64 MiB/1 million vertices/100 million comparisons/1 million rows/1 GiB output**. Candidate input remains capped at 128 MiB and rows at 64 KiB. A worldwide ADM0/ADM1 collection is not demonstrated to fit. Add indexed partition orchestration that preserves *global* unique-country/unique-state ambiguity decisions across partitions, including overlap, borders and holes; concatenating independent country results can manufacture false unique matches. Budget preprocessing, indexes and intermediate copies. Current strict-interior semantics correctly keep borders, overlaps and inconsistent state evidence unknown.

The raw selector excludes relations, unnamed features, incomplete selected ways, dateline-spanning ways and ways with vertices at absolute latitude >=85 degrees. Mean-of-vertices is a representative point, not an entrance or access guarantee. These exclusions need counted, source-linked residual policy; no boundary overlay repairs them. More than four source lineages or duplicate value/vintage conflicts fail. Source snapshots with incompatible native vintages need an explicit policy or different source selection, not silent precedence.

Implement the separate footprint constructor: pin the exact extraction polygons associated with the dated edition; preserve multipart geometry/holes and split longitude domains; calculate union, overlaps and full-cell containment; emit only cells proven wholly inside admitted extraction coverage. Record seam cells, islands, overseas territories, polar exclusions, failed objects and other residuals against an explicit intended-world inventory. Assign deterministic duplicate ownership while preserving lineage. Complete crossing ways do not extend proven areal coverage. Administrative boundaries and candidate counts cannot substitute for extraction evidence. The boundary producer intentionally emits empty footprints today. Only actual input processing and residual review can admit worldwide coverage; implementation fixtures establish algorithms alone.

Current producer parses each source twice and stores **all nodes**, not only selected-way references. It keeps the entire pinned raw set available for final checks and resume; sequential parsing does not permit deleting earlier raw inputs. Its single edition SQLite accumulates candidates/lineage and retains current-source nodes. A true one-source-at-a-time acquisition/deletion plan needs independently sealed source artifacts and a reviewed edition merger; it is not current functionality. The supervisor CLI does not count unrelated retained roots or coordinate jobs machine-wide; use an explicit external inventory/operator preflight and generic retained-path accounting. The 8 GiB process-tree commit ceiling is below the observed 16.36 GiB free physical RAM, leaving roughly 8.36 GiB for other activity at that instant; commit availability must still be checked separately. Installed total RAM alone does not admit this limit.

No defensible global completion time exists. The **48-hour ceiling applies only to the raw producer**, whose manifest rejects a larger `seconds` value; it is not an end-to-end build budget. Catalogue publication remains subject to its own 30-minute API ceiling, and acquisition, boundary preparation and complete orchestration require explicitly counted deadlines. Measure two-pass parsing, hashing, candidate writes, boundary comparisons and catalogue publication separately. Future estimate = measured stage workload/rate plus measured fixed overhead and a stated safety factor; measure dense sources and large boundary geometry before extrapolation. Download time needs a measured approved transfer rate; network capacity is unknown. Deadlines above are stop ceilings, never promises.
