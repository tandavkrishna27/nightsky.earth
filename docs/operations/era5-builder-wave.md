# Fixed 2025 ERA5 sample builder

13 October 2026. The offline builder is implemented; the real full-year artifact is **withheld**. At initial builder verification the installed pilot had 2/28 required completed chunks, with 26 missing; source retrieval subsequently continued in the separate retrieval lane. This builder lane made no source request, credential read, deployment, or public historical tool registration.

## Run after all inputs are staged

```powershell
npx tsx scripts/era5/build-pilot.ts --root .data/era5/pilot-2025 --geonames .data/geonames/cities500.json.gz
```

The normal command starts a separate worker with a hard 30-minute timeout and 4 MiB child-output buffer cap. The launcher rejects deadlines exceeding 30 minutes and forcibly kills stalled workers. Internal `--worker` and library calls have cooperative checks only; operators use the normal command. A killed worker can leave a lock or temporary output requiring explicit review. Existing published output is preserved until a successful atomic rename. The launcher deliberately retains an interrupted writer lock; another build rejects it until the operator reviews and resolves that state.

The only output path is `<pilot-root>/full-year-sample.json`. The printed measurement report contains its SHA256 and byte count; the digest covers the exact canonical JSON bytes. Timing and RSS are excluded from those bytes so identical verified inputs and the same runtime versions produce identical artifacts. An earlier published artifact also pins source provenance: coherently rehashed replacements fail instead of silently replacing it. Failed builds do not remove a previous artifact. Output paths cannot overwrite manifests, checkpoint ledgers, retrieval state or the shared writer lock.

## Required evidence and scope

The reviewed manifest has a fixed canonical SHA256 matching `pilot.py`: `e43315f64a34a586abda7e4f0ac434e82f0868d2f23bd124a09ba47545bd2400`. The builder requires exactly the reviewed 28 unique, completed chunks, their raw/decoded SHA256 values and byte counts, expected row counts and explicit missing-hour counts, decoder versions, experiment version `0001`, supplied cells, source DOI/profile and exact requested hourly date ranges. It rechecks all source hashes and the unchanged manifest/ledger before publication. Shared writer locking excludes the importer/downloader during the build. This is a local trusted checkpoint workflow, not authentication of a maliciously rewritten first ledger or an independent scientific re-decoding of every raw NetCDF file.

All requested chunks must exist; that does **not** mean every requested source hour is valid. Missing hours and null cloud values remain explicit and enter the expected dark-time denominator. A sparse but correctly evidenced input produces sparse sample statistics with missing counts, never a baseline or a full-coverage claim.

The artifact includes a self-contained `sourceProvenance` record validated with the shared source schema: Copernicus Climate Change Service (C3S)/ECMWF, ERA5 hourly single levels, DOI `10.24381/cds.adbb2d47`, reanalysis, CC BY 4.0 licence URL, and explicit NightSky.earth modification into derived hourly dark-time cloud aggregation. Scientific aggregation, source manifest and acquisition profile are unchanged.

## Resource accounting

Sources are traversed chronologically per selected cell/timezone with one decoded chunk buffered at a time. Decoded input is capped at 4 MiB even on reread. The parser admits at most 800 rows ×10 cells, at most 64,000 bytes of numeric values; three result arrays contain only fixed bins. The 32 MiB decoded-numeric ceiling is therefore bounded structurally. JSON text, parser objects, GeoNames loading and runtime overhead are separate from numeric arrays and appear in process RSS. Raw hashing uses 64 KiB streaming blocks and enforces the 32 MiB raw chunk limit. Retained raw files are capped at 256 MiB, the pilot directory at 1 GiB, and output at 4 MiB. The maximum staging scratch estimate includes the temporary artifact beside any prior artifact.

The printed report separates builder wall time, CPU seconds, process lifetime peak RSS, artifact bytes, prebuild pilot directory bytes, and prebuild bytes plus staged-output upper bound. Peak RSS includes GeoNames/runtime overhead and any earlier work in a library caller. The scratch figure is a conservative inventory-plus-output estimate, not a measured continuous peak. Queue/download timing belongs to retrieval evidence, not these builder measurements. These figures do not measure the MCP server, Hetzner, multi-year or global feasibility.
