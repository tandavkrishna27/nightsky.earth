# Private provider and quota migration checklist

This is a later activation checklist, not permission to copy credentials or enable sources. V1 remains API/search-only, with no bulk data or database.

1. Inventory the selected provider/account labels, admitted features, current free entitlements and private configuration paths without exposing values. Keys belong only in root-owned0600 `/etc/nightsky/production.env`, never GitHub build arguments, workflow logs or images. Recheck WeatherAPI trial/free transition and any optional astronomy entitlements before activation; disabled/unadmitted sources stay disabled.
2. Identify every consumer of each shared account, including local test servers. Stop them gracefully and verify no provider request is in flight. There must be one production ledger owner. Freeze the original ledger location after handoff so a local test cannot consume the same budget separately.
3. Each private checkpoint and its `.initialized` marker migrate together as a byte-identical pair. Graceful close removes its own `.lock`. If `.lock` or `.tmp` remains, stop and diagnose ownership/interrupted writes; never delete or transfer a live lock, truncate a ledger, reset usage, or initialize an already-used account as unused.
4. Preserve checkpoint version, account labels, policy bindings/import evidence, hourly/daily buckets, monthly usage, disabled/block-until flags and lastNow. Verify destination clock is not earlier than lastNow. A migration is not a new usage initialization. If exact accounting is missing, source activation remains blocked pending conservative verified account usage and a separately reviewed import.
5. Use a private authenticated administrator channel outside Git/logs. Copy to a private root-owned staging directory first. Verify source/destination SHA256 privately; check regular single-link nonsymlink files, size bounds, JSON validity and the matching exact provider policies without printing their content. Install each pair atomically while the service is stopped into the verified runtime directory, owner/group10001:10001, files0600, directory0700. Keep encrypted/offline recovery copies and document their retention privately.
6. Path names in production config are distinct `/state/<name>.json`: `NIGHTSKY_QUOTA_STATE_PATH`, `NIGHTSKY_LIGHT_POLLUTION_QUOTA_STATE_PATH`, `NIGHTSKY_SKY_QUOTA_STATE_PATH`, `NIGHTSKY_PUBLICUNIVERSE_QUOTA_STATE_PATH`. Do not mount server release records/config or a Docker socket into the application. Staging receives no secrets or ledgers.
7. Validate against the exact reviewed accounting implementation (`server/providers/quotaState.ts` and provider configuration modules). A validator that opens the live quota owner acquires a lock; it is not a read-only inspection. Perform any ownership/startup validation only during the approved single-writer handoff and close gracefully. Do not reserve/spend a credit just to test file ownership.
8. After separately authorized production startup, confirm loaded account identities and fail-closed errors using safe diagnostics. Approve a bounded real journey separately; no automatic request allowance follows from moving files. Preserve reservations across shutdown/restart/rollback. Rollback changes image, not consumed credits or schema compatibility.

No private file has been inspected, moved or initialized by this document. The deployment access check does not read quota files and cannot validate provider readiness.
