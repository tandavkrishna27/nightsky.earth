## Proposed thirteen-row matrix

**Every row still needs** an admitted civil-date start/end and endpoint meaning/precision, reuse/provenance and maintained-year applicability, plus matching radiant support across the entire declared activity window and local-plan validation. The final column adds row-specific missing fields and a finite source route; it does not authorize acquiring that source.

Peak columns are **MM-DD HH:mm** in the retained ISO UTC representation, separately for the year in the header. A dash means no admitted maximum for that row/year, not physical inactivity. NASA source identifiers are [2026 NTRS 20250009524, Table 3 p. 8](https://ntrs.nasa.gov/citations/20250009524) and [2027 NTRS 20260009360, Table 3 p. 9](https://ntrs.nasa.gov/citations/20260009360); exact retained files are [2026](../../data/events/meteor-peaks-nasa-2026.json) and [2027](../../data/events/meteor-peaks-nasa-2027.json).

In the radiant column, **anchor ± half-width** is the runtime's accepted solar-longitude domain in **degrees of geometric J2000 mean-ecliptic solar longitude**, not dates, activity length or a peak. Half-width = nominal fit days × 0.986 / 2. All eleven use the [retained GMN original fitted models](../../data/events/meteor-radiants-gmn-2021.json): [Moorhead, Clements and Vida, arXiv 2205.15423v1](https://arxiv.org/abs/2205.15423v1), original coefficients Table 1 and nominal windows Table 3, CC BY 4.0. Observation interval 2018-12-10–2021-05-22; evaluation in 2026/2027 is annual extrapolation. Published parameter errors are not propagated positional confidence intervals. An existing model is not a claim that every retained peak or requested night falls inside it.

## Independent planetary work: apparent planet-pair conjunctions

**Still missing:** the runtime's `planetary-conjunction` stream provides explicitly labeled relative-heliocentric solar alignments, not apparent conjunctions between two planets. Mercury/Venus greatest elongation is a separate supported full-angle event; it does not fill this gap. The urban-observer journey and product line 169 still require coverage reconciliation before broad planetary-event acceptance. This document selects no smaller launch subset and does not promote unsupported pair events.

**A bounded in-scope implementation can proceed independently of the meteor selection and without a new dataset.** The pinned MIT Astronomy Engine already provides local geocentric vectors, coordinate rotations and a generic root search. A conventional pair event can be defined as equality of the two planets' geocentric ecliptic longitudes, using an explicitly stated light-time/aberration/frame convention. That is a routine scientific implementation definition, distinct from minimum three-dimensional sky separation or closest physical distance. There is no existing general next-pair-conjunction adapter to expose unchanged; native `PairLongitude` and the adapter's correction convention must not be assumed interchangeable.

The finite prerequisite is a reviewed calculation contract and independent **matching-definition public reference cases**, rather than observation downloads or a new provider feed. A local implementation must establish cyclic-angle unwrap, forward/reverse relative motion, stationary/tangent behavior, multiple roots and interval completeness; a generic root solver plus an arbitrary scan step proves none of those. Bound requested bodies, date horizon, duration, iterations and results explicitly, with stable identity, inclusive endpoints and clear exhaustion/unresolved behavior. Preselect comparison limits from the reference precision/convention; label the event's global geometry and keep local horizon/darkness/detectability separately evaluated. Retain source/version/MIT notices and regression coverage through the shared schema, catalog, MCP and planner. The absence of a dataset dependency does not waive these correctness/reference gates.

**Disposition:** this calculation lane is technically independent and remains within the named V1 planetary scope. No new algorithm, pair-event fixture, source request or deployment is performed by this proposal. The owner decision requested here concerns the meteor set/year/precision; completing the separately bounded pair calculation need not wait for it. General closest-approach coverage remains a distinct unimplemented definition, not an alias to add during this matrix work.
