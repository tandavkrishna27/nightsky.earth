## Completion decision

### OpenWeather follow-up: public licence question resolved to concrete obligations

Fresh primary documents opened **18 October 2026**:

- [Detailed pricing](https://openweathermap.org/full-price) explicitly puts five-day/three-hour forecast in the permanent Free column: 60 calls/minute, 1,000,000/month, ODbL, attribution required. Its licence section expressly says ordinary application display does not require publishing application code/business logic; externally shared adapted weather databases carry share-alike. This supersedes relying solely on the older explainer's broad app wording. Account-specific accepted terms remain separate facts.
- [API guide licensing](https://openweathermap.org/guide) distinguishes displayed outputs (Produced Work) from restructuring/enriching weather data into a publicly available adapted dataset/API. Merely changing schema does not remove data origin. This is the provider's documented distinction, not a legal ruling about NightSky.
- [Five-day endpoint documentation](https://openweathermap.org/api/forecast5) matches the fixed `/data/2.5/forecast` adapter. [FAQ attribution](https://openweathermap.org/faq#license) requires visible `Weather data provided by OpenWeather`, a website hyperlink and the OpenWeather logo. A text link alone does not establish full rendered-logo compliance.
- Current linked [sale terms, G2.4](https://openweather.co.uk/api/files/file/OpenWeather_T%26C_of_sale.pdf) distinguish CC BY-SA 4.0 products/services from ODbL data/database. They also preserve ownership markings. The [2025 explainer](https://openweathermap.org/storage/app/media/documents/License_explainer_25%20Feb_25.pdf) remains indexed but its direct URL returned 404; it is historical supporting evidence rather than the only operative source.
- [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), sections 4.2–4.6, requires notices for public database conveyance, attribution/licence notice for Produced Works, and share-alike plus an accessible machine-readable database or alteration-method offer when a derivative database is publicly used. The licence does not by itself require relicensing unrelated application code.

Implementation finding: `server/providers/weather/openWeather.ts` line 6 already supplies provider documentation URL and a credit, but `licenseUrl` is `https://openweathermap.org/terms`, the website-use terms rather than the data licence. The current credit says `Weather data by OpenWeather`; it does not carry an explicit ODbL notice or normalization notice. The adapter selects/restructures weather samples and returns structured arrays over MCP, while retaining no response cache. Thus an ordinary final observing explanation fits the documented output-display category as an engineering interpretation; the structured sample transfer should conservatively retain ODbL rights/notices rather than assume all MCP output is only a Produced Work. Zero caching does not eliminate the transformation or notice duties.

Concrete minimal implementation recommendation for the coordinating lane (subsequently implemented below): set that existing `licenseUrl` to the ODbL text URL; use the FAQ's exact provider credit with an explicit provider website link, data-licence link and a short selection/field-normalization notice. Preserve this source record through the existing separate-provider output. The release surface should display the official logo where weather appears; record text-only host compliance separately rather than asserting a logo can be shown by a plain string. If conservatively treating shared normalized samples as derivative data, mark the OpenWeather sample component ODbL and supply a public, machine-readable normalization-method offer under section 4.6 (the actual transformation source or equivalent complete method, not private data/key material). This closes the generic “research Free rights” task with a bounded compliance implementation; no paid subscription or blanket application relicensing is indicated by the reviewed current documentation. It does not itself grant runtime admission.
