## What remains achievable locally

The latest code already supplies `scripts/osm/boundary-metadata.ts`, `scripts/osm/build-source-catalogue.ts`, `scripts/era5/build-observation-aggregates.ts`, `scripts/era5/build-release.ts` and `scripts/plugin-operator-preflight.ts`, with actual runtime release selection in `server/mcp/registerTools.ts`. Do not commission those same implementations again.

Specific remaining local build candidates are bounded preprocessing/orchestration for actual admitted inputs that exceed current shard limits; preparation of explicit geographically justified cell/timezone mappings; source extraction coverage/footprint production with defensible completeness evidence; and any meteor season/model integration justified by cleared sources. These are conditional tasks with input contracts, not evidence that every one needs a new general framework. The boundary producer deliberately outputs empty footprints. It accepts split GeoJSON and bounded geometry; it does not derive a worldwide boundary edition. History accepts decoded pinned inputs and at most ten mapped cell/zone pairs per aggregation; it does not retrieve worldwide hours, independently validate upstream raw bytes or infer correct geographic zones. The Windows raw-source supervisor is not cross-platform hard process enforcement. A Linux producer supervisor is only a new local task if Linux bulk building becomes an explicitly chosen requirement; Linux serving support is a separate question.

Prepared-data work can construct/rehearse explicit plans, shard layouts, provenance and release inventories from already admitted local inputs. Real edition production, full baseline eligibility, refresh costs and selected-host fit require measured actual inputs. Source proposals in the G/H lane documents own exact products/requests/limits; this matrix does not authorize a substitute acquisition plan. Keep synthetic engineering resources separate from observed data resources.

Release preparation can align the ready packet, manifest placeholders, policy drafts and host/client evidence templates with the current five-skill/fourteen-tool inventory. Final owner identity, hostname, retention and budget facts cannot be filled by code. No demonstrated must-fix generic local software defect is established by this audit. Do not turn all held gates into another broad implementation wave or repeat already completed audits/tests merely to raise the heading count.

Known owner information is settled: brand **NightSky.earth**, personal publisher in **India**, monitored support **nightsky.earth2026@gmail.com**. Exact legal identity is **not verified**, not an empty invitation to invent a name. Host work is intentionally later. Claude is explicitly deferred; Codex is acceptable.
