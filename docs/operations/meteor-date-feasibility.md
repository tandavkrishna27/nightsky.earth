## Why dates remain unavailable

Existing `solarLongitudeJ2000` evaluates reversed geometric heliocentric Earth position. Astronomy Engine's solar search instead supplies apparent longitude of date. Neither can be substituted into A58 based solely on its J2000 label. Rounding a solved crossing to a calendar day would still conceal the unresolved convention and source endpoint meaning. The reported typical limits and one-degree analysis bins are not precise physical start/end guarantees.

No annual root solver was accepted, so no derived boundary instants were used as their own test oracle. Prior GMN checks validate that separate radiant route; they do not independently validate A58 season boundaries. Calendar/year/date-line and inclusive-overlap tests become implementation requirements only after the scientific gate clears.

The exact next gate is a public primary description or versioned author/provider code tied to the A58 analysis that specifies origin, ecliptic/equinox, correction convention and input time scale. Then select a matching independent ephemeris reference with explicitly equivalent settings, validate every retained boundary across supported years, state the accuracy/rounding and chosen year horizon, and test year transitions/date-line presentation and inclusive query overlap. Keep generic recurrence separate from year-specific peak/outburst forecasts and preserve all existing radiant fit limits. No author contact is required or authorized by this wave.
