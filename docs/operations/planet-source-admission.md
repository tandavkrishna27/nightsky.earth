# Planet source admission

The offline admission contract now supports `kind: osm-planet` and `effectiveClip.status: planet-domain`. The historical field name is retained for compatibility; this variant contains no clip payload, provider polygon, extraction procedure, or searched coverage. Extracts still require a bound effective clip and independently trusted effective-clip review.

The strict `planet-domain-v1` descriptor binds the dated public source URL, edition, named provider, retained provider whole-world evidence, provider version/ETag/MD5, measured raw SHA-256 and bytes, native vintage and its retained observation, exact longitude/latitude source domain [-180,-90,180,90], and unchanged `named-complete-way-v1-polar85` policy. Its only allowed coverage claim is `source-domain-only`. Unknown coverage fields and partial-world domains fail schema validation. The world domain does not change polar/date-line exclusions or imply complete search.

`createPlanetDomainDescriptor(rawPath, descriptor, descriptorPath)` streams an already retained local raw file through SHA-256 in 64 KiB chunks, checks exact size and mutation, verifies both evidence pins, and returns deterministic canonical UTF-8 bytes and their SHA-256. All linked evidence paths resolve relative to the descriptor parent directory in creation, admission, production and assembly, including nested descriptors. It performs no acquisition or file writes. The native observation is an exact JSON object with `schemaVersion: 1`, `kind: native-vintage-observation`, `raw: {bytes, sha256}`, and `nativeVintage`. A parser must produce that observation from the native header. This helper checks linkage, not parser truth; the independently trusted payload-validation review remains necessary. A plain metadata declaration is not authenticated provider evidence.

A planet bundle requires a separate `planet-domain` review alongside provenance, payload, rights and admission reviews. Every review is bound to the full source subject digest and independently allowlisted. Wrong payload URL, edition, byte count or SHA is quarantined. Changing vintage, provider evidence or selection policy invalidates existing receipts. The file gate verifies retained descriptor bytes and exact native observation linkage. ODbL conditions and public machine-readable offers remain required as applicable.

## Production remains gated

No real planet descriptor is checked in: the 95,380,942,829-byte source has not been received, and its local SHA-256/native timestamp remain unavailable. Synthetic tests use three local bytes and do not establish real-source provenance or performance.

The immutable retained policy contains the existing boundary and extract inventory only. Therefore the CLI quarantines an `osm-planet` bundle with `policy-source-not-found` even if hypothetical reviews exist. A separately reviewed pinned inventory/policy revision must explicitly admit the actual source record; candidate files cannot select that baseline.

The producer has an explicit planet branch: replace `clipSha256` with `sourceDomain: {kind: "planet-domain-v1", path: absoluteDescriptorPath, bytes, sha256}`. The branches are exclusive. It loads the pinned descriptor and both retained evidence artifacts, verifies exact semantics and raw/URL/native-vintage/policy binding, and repeats verification around parsing and before completion. Actual XML/PBF header vintage validation and actual raw hashing remain independent checks; descriptor declarations cannot replace them. The catalogue revision includes domain kind/bytes/hash while excluding local descriptor paths. Resume binds the complete manifest and rejects changed domain evidence.

Completion carries `sourceDomains` entries with `sourceId` plus the domain pin. The assembly plan must include the same ordered list. Python preflight and TypeScript assembly both reject missing/substituted domain pins, TypeScript validates descriptor semantics, bytes, both linked evidence pins and exact native observation on initial and final load, and the supervisor automatically accounts for retained descriptor and linked evidence files. Shared evidence paths are counted once; overlap with explicit retained paths is rejected. Descriptor bytes are retained at their original pinned location and rechecked before assembly completion. No automatic searched footprints are generated.

This closes the local producer/assembly contract gap. Independent operator-controlled source policy and trusted reviews remain a separate preparation gate, as for existing extracts. The production CLI still cannot admit the real planet before an approved inventory revision and actual retained raw/native evidence exist. No download, provider job or runtime promotion is authorized by these functions.

## Production invocation binding — 17 October 2026

[The production gate](production-source-admission.md) now runs before producer/assembly execution and again before completion and resume. An exact independently pinned envelope binds the actual raw manifest and assembly plan, every source bundle, normalized boundary lineage and consumed geometry/footprint pins. The gate derives the immutable operator policy and a fixed empty trusted-review allowlist; candidate policy/trust files and copied snapshots cannot grant admission. Source subjects and policy digests, full invocation hashes, producer manifest/revision/policy and fixed executable context participate in the snapshot. Windows production retains read leases across stages, refusing writes/deletes without another raw allocation. The raw CLI also holds its retained input leases.

Provider-aware Natural Earth conditions come from explicit trusted records rather than candidate labels; legacy geoBoundaries conditions stay unchanged. Real planet and selected Natural Earth records/reviews are still unavailable. This implements the enforcement path and does not fabricate or grant its missing actual-source inputs. The direct producer-to-catalogue bridge fails before a job because it has no admitted boundary assembly contract; production uses supervised membership assembly. Test-owned tiny reserved-domain launchers exercise library primitives and expose no production CLI bypass.

## Assembly fit

`membership-assembly.ts` parses all three completion pins (candidates, exclusions, lineage) under an individual **128 MiB** maximum before creating membership staging. Footprints have the same maximum. Producer aggregate output limits cannot override these individual caps. Oversized evidence must result in retained failure evidence and a revised capacity decision, not an automatic ceiling increase. Boundary membership and publisher limits remain additional constraints; no partition merger is present.

The capacity plan is an advisory allocation calculation, not planet throughput, candidate-count, intermediate-size or serving-fit proof. A bounded preparation attempt may still fail under unchanged limits. Source-domain admission supplies no searched cells: completed policy scanning and independent footprint evidence are still required.

Validation: focused admission and assembly TypeScript tests, producer Python tests, Windows supervised assembly integration and tools TypeScript typecheck passed. The new planet acceptance/descriptor/producer/supervised assembly tests were observed failing before their corresponding implementation. The end-to-end fixture uses tiny synthetic XML; PBF parser-dependent tests remain skipped when pyosmium is unavailable. Parent integration owns the combined suite.
